# AstroImageSelector Rust 性能记录

## 基准环境

- CPU：Intel Core i7-10700，8 核 16 线程
- GPU：NVIDIA GeForce RTX 2060 SUPER，驱动 576.83
- 数据：8 张 `2048 × 2048`、16 位浮点 FITS
- 指标：进程墙钟时间，包含启动、FITS 读取、星点检测、测量、SNR、结果和缓存写入

可复现脚本和受控数据生成器位于当前目录。`generate_fixture.py` 生成基准 FITS，`scan_fixture.py` 生成 1000 个文件扫描样本，`measure_components.ps1` 统计冷缓存和热缓存运行。

## 基线

| 场景 | 时间 |
|---|---:|
| 8 张首次分析，单线程 | 约 18.9 秒 |
| 4 线程首次分析 | 约 7.4 秒 |
| 7 线程首次分析 | 约 7.4 秒 |
| 1000 个 2×2 FITS，首次分析 | 约 0.69 秒 |
| 1000 个 2×2 FITS，缓存命中 | 约 0.70 至 0.96 秒 |

各阶段的时间占主导顺序为：星点检测 > FITS 读取 > SNR > Gaussian 测量。测量通常不足 50 毫秒，不是当前瓶颈。

## 背景缓存优化

分析器在检测器生命周期内按中心区域尺寸和阈值复用背景统计。早期实现每张图创建新检测器，导致背景估计重复。优化后每个分析工作线程拥有独立检测器，并在同一批分析内复用背景统计。

同一组受控数据，单线程阶段记录显示：

- 首张图的星点检测包含背景估计，约 2.2 秒。
- 后续图像使用已缓存的背景统计，检测约 0.58 秒。
- 8 张图的首次总计算由约 29.1 秒下降至约 18.2 秒，约 37% 提升。

缓存键和背景扣除规则由回归测试固定。多线程提升仍受 CPU、内存带宽和系统负载影响。4 线程已达到当前测试机的吞吐平台期，继续增加线程没有稳定收益。

缓存版本 2 增加了命中快路径。有效记录直接返回结果，不再读取每张 FITS 的头部，也不再重新运行计算。8 张图的独立进程总耗时在 0.13 至 0.57 秒之间，波动主要来自进程启动和磁盘缓存状态。

修正前，命中结果虽然被读入，待计算索引仍包含全部文件，导致缓存目录仍会重新分析。版本 2 同时修正了这个索引回填错误。

## 已验证的固定行为

- 缓存命中时不重新运行 GPU 初始化。
- 读图失败的结果不写入分析缓存。
- 缓存结果按相对路径、文件大小和修改时间失效。
- 平场在分析前排除。
- FITS 读取和预览保持 25/25 回归样本对照。
- 不同线程数下，8 张图的完整结果 JSON 保持一致。

## 未采用的尝试

快速 SNR 实现曾实现相同公式并在小样本上逐位一致，但整批回归测试受系统负载影响，未形成稳定收益，因此没有替换正式路径。

预览的统计拉伸保持既定的 NaN 和常量帧像素行为。界面层对全零纹理显示“预览没有可显示的有效亮度”，以避免用户把坏纹理误认为全黑图像。
